# speedtest.py — замер скорости скачивания

Консольный скрипт на Python (тестовое задание ETOLEGKO).

Скрипт принимает адрес ресурса, делает к нему **10 последовательных запросов**, каждый раз
дочитывает тело ответа до конца, считает **среднее время одного запроса** и **общий объём
скачанных данных**, после чего печатает **скорость скачивания**.

Зависимостей нет: только стандартная библиотека Python (`urllib`, `time`, `argparse`).

## Требования

- Python 3.9+ (проверено на Python 3.14)
- доступ в сеть до указанного адреса

## Запуск

```bash
python3 speedtest.py <URL>
```

Пример с «тяжёлым» ресурсом (Cloudflare отдаёт ровно 5 000 000 байт на запрос):

```bash
python3 speedtest.py 'https://speed.cloudflare.com/__down?bytes=5000000'
```

Можно указать любую тяжёлую картинку или файл, например `https://proof.ovh.net/files/10Mb.dat`.
Учтите: часть сайтов (например, Викимедиа) отвечает `429` на запросы без «браузерного»
`User-Agent` — тогда скрипт покажет ошибки и код выхода `1`.

### Флаги

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `URL` (позиционный) | — | адрес ресурса, только `http://` или `https://` |
| `-n`, `--runs` | `10` | сколько запросов сделать последовательно |
| `--timeout` | `30` | таймаут одного запроса, секунды |

Быстрый прогон на 3 запроса:

```bash
python3 speedtest.py 'https://speed.cloudflare.com/__down?bytes=5000000' -n 3
```

## Единицы измерения

- **Мбит/с** — основная единица вывода, десятичная: `1 Мбит = 1 000 000 бит` (так скорость
  указывают провайдеры).
- **МБ/с** — в скобках, для привычного понимания скорости загрузки файлов:
  `1 МБ = 1024 × 1024 = 1 048 576 байт`.
- **МБ** для объёма — тоже `1 МБ = 1024² байт`.

Формулы:

```
объём (байт)        = сумма байт всех успешных запросов
время (с)           = сумма длительностей всех успешных запросов
среднее время (мс)  = время / число успешных запросов × 1000
скорость (Мбит/с)   = объём / время × 8 / 1 000 000
```

## Пример вывода

Реальный прогон (10 запросов по 5 000 000 байт):

```
Адрес: https://speed.cloudflare.com/__down?bytes=5000000
Запросов: 10 последовательно
Скачиваю...

Успешных запросов: 10 из 10
Скачано всего: 47.68 МБ
Суммарное время: 17.116 с
Среднее время запроса: 1711.6 мс
Скорость скачивания: 23.37 Мбит/с (2.79 МБ/с)
```

## Коды выхода

| Код | Когда |
| --- | --- |
| `0` | хотя бы один запрос удался, отчёт напечатан |
| `1` | ни один запрос не удался (все ошибки выведены в stderr) |
| `2` | неверные аргументы: `--runs < 1`, `--timeout <= 0`, не http(s) адрес |

Если упала часть запросов, отчёт всё равно печатается: в stderr выводятся строки
`[ошибка] попытка N: …`, а статистика считается по успешным попыткам.

## Тесты

Тесты не ходят в интернет: они поднимают локальный `ThreadingHTTPServer` на `127.0.0.1:0`
и раздают эталонный набор байт.

```bash
python3 -m unittest discover -s tests -v
```

Ожидаемый результат: `Ran 16 tests ... OK`.

## Как устроен замер

- Запросы идут строго по одному: следующий стартует после полного завершения предыдущего
  (тест `test_requests_are_sequential` проверяет, что одновременно активен максимум один запрос).
- Время засекается через `time.perf_counter()` перед отправкой запроса и останавливается
  после того, как тело ответа прочитано целиком.
- Скорость считается по суммарным объёму и времени: `объём / время`, а не средняя из скоростей.

## Ограничения

- Один поток, без параллельных соединений — это осознанно: цель измерить честную
  последовательную скорость, а не пропускную способность канала при конкуренции.
- Если сервер/CDN отдаёт из кэша или сжимает ответ, цифры будут выше реальной скорости канала.
- Первый запрос включает DNS-резолв и TLS-хендшейк, поэтому он обычно медленнее остальных.
- Замеряется только скачивание; скорость отдачи не измеряется.
